<h2>Google تعيد كتابة قواعد وكلاء الذكاء الاصطناعي</h2>
<p>أعلنت Google أن جميع <strong>وكلاء الذكاء الاصطناعي وأدوات الوصول المماثلة</strong> يجب أن تستخدم <strong>خوادم Workspace MCP (بروتوكول سياق النموذج)</strong> أو <strong>Workspace CLI</strong> للوصول إلى بيانات Workspace — وليس واجهات REST API التقليدية. يبدأ التطبيق التقني في <strong>1 فبراير 2027</strong>، مما يمنح المطورين حوالي شهرين للانتقال.</p>
<p>كلا الأداتين <strong>متاحتان الآن بشكل عام</strong>، وتغطيان <strong>Gmail وDrive وDocs وSheets وSlides وCalendar وChat وTasks</strong>، مع <strong>انضمام Keep قريباً</strong>. يأتي التغيير مع ملحق أدوات Workspace AI جديد، وتسعير استخدام ثنائي المستوى، وضوابط إدارية محسنة — مما يمثل أهم تحول في كيفية تفاعل أدوات الطرف الثالث مع Google Workspace منذ إطلاق المنصة.</p>

<h2>ما الذي يتغير في 1 فبراير 2027</h2>
<p>التغيير الجوهري هو انتقال البروتوكول:</p>

    <tr><td>الوكلاء تحدد أنماط وصول البيانات الخاصة بها</td><td>وصول موحد عبر بروتوكولات تديرها Google</td></tr>
    <tr><td>رؤية محدودة لسلوك الوكلاء</td><td>تأكيدات مستخدم ومراجعة تدقيق مدمجة</td></tr>

<h2>ما هو MCP ولماذا هو مهم؟</h2>
<p><strong>MCP (بروتوكول سياق النموذج)</strong> يصبح البروتوكول القياسي لوكلاء الذكاء الاصطناعي للتفاعل مع الأدوات ومصادر البيانات الخارجية. طورته Anthropic أصلاً وتم تبنيه سريعاً عبر الصناعة، يوفر MCP طريقة منظمة لوكلاء الذكاء الاصطناعي لـ:</p>
<ul>
  <li><strong>اكتشاف</strong> الإجراءات المتاحة (قراءة البريد الإلكتروني، إنشاء مستند، إلخ)</li>
  <li><strong>طلب الأذونات</strong> من خلال تأكيدات المستخدم الموحدة</li>
  <li><strong>تنفيذ الإجراءات</strong> مع مسارات تدقيق مدمجة</li>
  <li><strong>احترام الحدود</strong> التي يضعها المسؤولون</li>
</ul>
<p>اعتماد Google لـ MCP في Workspace مهم لأنه يصادق على MCP كمعيار ناشئ — عندما تتطلبه أكبر مجموعة إنتاجية في العالم، يجب على نظام وكلاء الذكاء الاصطناعي بأكمله أن يتبع.</p>

<h2>مستويا الاستخدام</h2>
<p>تقدم Google <strong>نظام استخدام ثنائي المستوى</strong> للوصول إلى Workspace API وMCP، بدءاً من Gmail وDrive وCalendar:</p>
<ul>
  <li><strong>المستوى القياسي:</strong> مضمن مع خطط Workspace الحالية، يغطي أنماط الاستخدام النموذجية لمعظم المؤسسات</li>
  <li><strong>المستوى المتميز:</strong> لحالات استخدام الوكلاء عالية الحجم أو المتقدمة التي تتجاوز الحدود القياسية</li>
</ul>

<h2>الأمان: المحرك الحقيقي</h2>
<p>خطوة Google تتعلق جوهرياً بـ<strong>الأمان والسيطرة</strong>. وكلاء الذكاء الاصطناعي التي تصل إلى بيانات Workspace عبر واجهات REST API الخام تخلق عدة مخاطر:</p>
<ul>
  <li><strong>تسريب البيانات:</strong> وكيل لديه وصول API يمكنه نسخ بيانات حساسة بصمت إلى خوادم خارجية</li>
  <li><strong>إجراءات غير مراقبة:</strong> بدون تسجيل موحد، لا تستطيع المؤسسات تتبع ما فعلته الوكلاء ببياناتها</li>
  <li><strong>تضخم الأذونات:</strong> الوكلاء غالباً ما تطلب أذونات أوسع مما تحتاج، مما يخلق أسطح هجوم</li>
  <li><strong>الذكاء الاصطناعي الظلي:</strong> الموظفون يربطون وكلاء الذكاء الاصطناعي بـ Workspace دون موافقة تكنولوجيا المعلومات</li>
</ul>

<h2>ضوابط المسؤولين</h2>
<p>تطرح Google في الوقت نفسه قدرات إدارية محسنة:</p>
<ul>
  <li><strong>قائمة الوكلاء المسموح بها:</strong> يمكن للمسؤولين تحديد وكلاء الذكاء الاصطناعي المسموح لها بالوصول إلى بيانات Workspace</li>
  <li><strong>ضوابط لكل خدمة:</strong> تمكين وصول الوكلاء إلى Gmail مع حظر الوصول إلى Drive، على سبيل المثال</li>
  <li><strong>مراقبة الاستخدام:</strong> لوحات معلومات في الوقت الفعلي تعرض نشاط الوكلاء عبر المؤسسة</li>
  <li><strong>تكامل الامتثال:</strong> إجراءات الوكلاء تُدمج في سير عمل الامتثال واكتشاف المعلومات الإلكتروني الحالية</li>
</ul>

<h2>ما يجب على المطورين فعله</h2>
<p>للمطورين الذين يبنون وكلاء ذكاء اصطناعي تتفاعل مع Google Workspace، قائمة الانتقال واضحة:</p>
<ol>
  <li><strong>اعتماد خوادم Workspace MCP</strong> للتواصل بين الوكلاء وWorkspace (متاح الآن)</li>
  <li><strong>أو استخدام Workspace CLI</strong> كمسار تكامل بديل</li>
  <li><strong>إزالة استدعاءات REST API المباشرة</strong> من كود الوكلاء قبل 1 فبراير 2027</li>
  <li><strong>تنفيذ تدفقات تأكيد المستخدم</strong> كما تتطلب البروتوكولات الجديدة</li>
  <li><strong>مراجعة ملحق أدوات Workspace AI</strong> لشروط الخدمة الجديدة</li>
  <li><strong>التخطيط للاستخدام المتدرج</strong> والتأكد من أن نموذج التسعير يراعي تكاليف المستوى المتميز المحتملة</li>
</ol>

<h2>الصورة الأكبر: MCP يصبح المعيار</h2>
<p>إلزام Google بـ MCP هو جزء من تقارب صناعي أوسع:</p>
<ul>
  <li><strong>Anthropic</strong> أنشأت MCP وتستخدمه على نطاق واسع في نظام أدوات Claude</li>
  <li><strong>OpenAI</strong> و<strong>Cisco</strong> قدمتا مؤخراً أُطر أدوات وكلاء الذكاء الاصطناعي المتوافقة مع مبادئ MCP</li>
  <li><strong>Microsoft</strong> لديها إطار وكلاء خاص بها لكنها تتزايد في التوافقية مع MCP</li>
  <li><strong>اعتماد المؤسسات:</strong> المنصات الكبرى توحد معاييرها على واجهات متوافقة مع MCP لوصول الوكلاء</li>
</ul>

<h2>الخلاصة</h2>
<p>يمثل الموعد النهائي لـ MCP من Google في فبراير 2027 نهاية الوصول غير المنظم لوكلاء الذكاء الاصطناعي إلى بيانات المؤسسات. من خلال إلزام جميع الوكلاء باستخدام خوادم MCP أو CLI، تحل Google في الوقت نفسه مشكلة الأمان (الوصول غير المدقق للبيانات)، ومشكلة تحقيق الإيرادات (الاستخدام المتدرج)، ومشكلة النظام البيئي (البروتوكولات الموحدة). للمطورين، الرسالة واضحة: انتقلوا الآن أو اخسروا الوصول إلى Workspace. للمؤسسات، الرسالة أوضح: وكلاء الذكاء الاصطناعي تصبح جزءاً مُداراً وقابلاً للتدقيق من مكدس تكنولوجيا المعلومات — وليس خدمة ظلية يربطها الموظفون بأنفسهم.</p>
