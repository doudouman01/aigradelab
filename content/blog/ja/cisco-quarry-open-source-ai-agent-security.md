<h2>CiscoがAIエージェントのセキュリティ問題に取り組む</h2>

<p>AIエージェントがより自律的になるにつれ——コードの記述、Webブラウジング、ファイル管理、API呼び出し——<strong>誰がエージェントを監視するのか</strong>という問いが急務となっています。Ciscoの答えが<strong>Quarry</strong>です。AIエージェントをリアルタイムで監視し、異常な動作を検知するオープンソースの行動検知エンジンです。</p>

<p>このツールはGitHubで公開されており、幅広いシナリオに対応しています：シングル・マルチターンのLLM会話、エージェンティックなツール使用、Model Context Protocol（MCP）を介したインタラクション、マルチモーダル入力など。<strong>Claude Code</strong>、<strong>Codex</strong>、その他のMCP対応エージェント向けのプラグインがすでに利用可能です。</p>

<h2>なぜAIエージェントのセキュリティが今重要なのか</h2>

<p>既存のAIセキュリティツールの多くは、モデルレベルで何が起こるかに焦点を当てています——プロンプトインジェクション、ジェイルブレイク、有害な出力など。Quarryは異なるアプローチを取ります：エージェントが何を言うかだけでなく、何を<em>するか</em>を監視します。</p>

<p>現代のAIエージェントは以下のことが可能であるため、この違いは重要です：</p>

<ul>
<li>サーバーやローカルマシンでコードを実行する</li>
<li>ファイルの読み取り、書き込み、削除を行う</li>
<li>外部サービスへのAPI呼び出しを行う</li>
<li>Webを閲覧し、ライブWebサイトとインタラクトする</li>
<li>複雑なワークフローで複数のツールを連鎖させる</li>
</ul>

<p>チャットボットに不適切な発言をさせるプロンプトインジェクションは一つの問題です。しかし、自律型コーディングエージェントに本番データベースを削除させるプロンプトインジェクションは、まったく別次元の問題です。Quarryは後者のシナリオのために構築されています。</p>

<h2>Quarryの仕組み</h2>

<p>Quarryは、AIエージェントとそのツールの間に位置する行動検知レイヤーとして機能します。<strong>Cisco AI Security & Safety Taxonomy</strong>をフレームワークとして使用し、設定可能なルールセットに基づいてエージェントのアクションを評価します。</p>

<p>主な機能：</p>

<ul>
<li><strong>ルールベースの検知：</strong> セキュリティチームが疑わしい行動の定義を設定——不正なファイルアクセス、予期しないネットワーク呼び出し、権限昇格の試み、データ窃取パターンなど。</li>
<li><strong>マルチターン認識：</strong> Quarryは会話のターンを超えてエージェントの行動を追跡し、単一のプロンプトではなく段階的に展開する攻撃を検出します。</li>
<li><strong>MCP統合：</strong> Model Context Protocolのネイティブサポートにより、Quarryはエージェントがアクセスできる特定のツールを監視し、異常な使用パターンを検出できます。</li>
<li><strong>プラグイン対応アーキテクチャ：</strong> Ciscoは人気のあるエージェントフレームワーク向けのプラグインを提供し、コミュニティにさらなる開発を奨励しています。</li>
</ul>

<p>プロジェクトのGitHubリポジトリには、インストール手順、対応Pythonバージョン、設定例、ルール作成ガイドが含まれています。</p>

<h2>大局観：AIエージェントセキュリティは新しいカテゴリ</h2>

<p>Quarryはより大きなトレンドの一部です。AIエージェントがデモから本番環境へ移行するにつれ、エージェントセキュリティという新しいカテゴリ全体が生まれつつあります：</p>

<ul>
<li><strong>Cisco AI Defense</strong>——Ciscoの商用AIセキュリティスイート。現在はOpenAIのCodexを使って完全に開発されており、四半期ではなく数週間で機能が提供されています。</li>
<li><strong>Anthropicの段階的承認システム</strong>——新しいClaude Shipバンドルの一部で、コード変更がリスクレベルで分類され、異なるレベルの人間の承認が必要になります。<a href="/ja/blog/claude-ship-ai-code-automation">詳しくはこちら</a>。</li>
<li><strong>OpenAIのDaybreak Defense Network</strong>——Ciscoとのサイバーセキュリティパートナーシップで、AIを活用した脅威トリアージを探求しています。</li>
</ul>

<p>パターンは明確です：最も高性能なエージェントを構築している企業が、ガードレールも構築しています。問題は、Quarryのようなオープンソースツールがエージェント開発のスピードに追いつけるかどうかです。</p>

<h2>Quarryを使うべき人</h2>

<p>Quarryは主に以下のような人々に関連があります：</p>

<ul>
<li><strong>開発チーム</strong>——本番環境でAIコーディングエージェント（Claude Code、Codex、Cursor）を運用している。</li>
<li><strong>セキュリティチーム</strong>——組織全体のAI駆動ワークフローの監視を担当している。</li>
<li><strong>プラットフォーム構築者</strong>——エージェンティックなAI製品を開発しており、ゼロから構築せずに検知レイヤーが必要。</li>
</ul>
