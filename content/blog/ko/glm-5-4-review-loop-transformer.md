<h2>GLM-5.4 한눈에 보기</h2>

Loop Transformer는 진정한 혁신입니다 — 레이어를 쌓는 대신 재사용하는 것은 컴퓨팅 비용을 3배로 늘리지 않으면서 모델을 더 똑똑하게 만드는 우아한 접근법입니다. 그러나 이 모델은 제한된 가용성, API 접근 불가, 공식 벤치마크 미공개로 인해 제약을 받고 있습니다. 현재로서는 AI 아키텍처의 미래를 엿보는 매력적인 프리뷰이며, Claude Fable 5.2나 GPT-6.2 Astra를 대체할 일상적인 도구는 아닙니다.

<h2>Loop Transformer란?</h2>

<p>2026년에 출시된 모든 주요 AI 모델은 같은 방법을 따랐습니다: 레이어를 더 쌓고, 파라미터를 더 추가하고, 더 많은 데이터로 학습합니다. GLM-5.4는 그 패턴을 깨뜨립니다. 레이어를 추가하는 대신, Z.ai는 기존 레이어를 더 열심히 작동시킵니다.</p>

<p>작동 원리는 이렇습니다: GLM-5.4는 약 7,500억 개의 파라미터를 78개의 저장 레이어에 배치합니다. 그러나 그중 28개 레이어 — 네트워크 중간의 "루프 블록" — 는 공유 가중치로 순전파 패스당 2번 실행됩니다. 결과적으로 78레이어 모델의 파라미터 저장공간을 사용하면서 토큰당 106회의 실효 레이어 패스를 달성합니다.</p>

<p>Z.ai는 이 접근법으로 GLM-5.4가 2조~3조 파라미터 모델의 지능에 필적할 수 있다고 주장합니다. 이것이 부분적으로라도 사실이라면 중요한 아키텍처 돌파구입니다 — 컴퓨팅 비용을 비례적으로 확장하지 않으면서 더 똑똑한 모델을 구축할 수 있다는 것을 의미합니다.</p>

<h3>루프의 실제 작동 방식</h3>

<p>아키텍처는 세 섹션으로 구성됩니다:</p>

<ul>
  <li><strong>Prelude 레이어 (1–26):</strong> 토큰당 1회 실행. 입력의 초기 표현을 구축합니다.</li>
  <li><strong>Loop 레이어 (27–54):</strong> 이 28개 레이어는 공유 가중치로 2회 실행됩니다. 토큰별 게이트가 각 루프 반복의 출력이 residual stream에 기록되는 양을 제어합니다. 패스 1에서 게이트는 작게 유지되어 모델이 글로벌 컨텍스트를 구축합니다. 패스 2에서 게이트가 더 크게 열리며 패스 1의 컨텍스트로 표현을 정제합니다.</li>
  <li><strong>Coda 레이어 (55–78):</strong> 1회 실행. 최종 출력을 생성합니다.</li>
</ul>

<p>영리한 트릭: 루프 블록의 두 번째 패스에서 모델은 패스 1에서 선택된 스파스 Key-Value (KV) 캐시와 attention 인덱스를 재사용합니다. 자체 로컬 슬라이딩 윈도우 캐시(보고에 따르면 128 토큰)만 유지합니다. 이는 두 번째 루프 반복이 상대적으로 적은 메모리 오버헤드를 추가한다는 것을 의미합니다.</p>

<h2>성능에 대해 알려진 것</h2>

<p>여기서부터 복잡해집니다. Z.ai는 공식 벤치마크도 모델 카드도 공개하지 않았습니다. 팀원은 점수가 나중에 공개될 것이라고 말했습니다. 현재 있는 것은 서드파티 테스트와 Z.ai 자체의 내부 절제 연구입니다.</p>

<h3>서드파티 결과: KingBench 4</h3>

<p>AICodeKing의 KingBench 4 하니스는 GLM-5.4를 6개의 코딩 프로젝트에서 테스트했습니다. 결과:</p>

<ul>
  <li><strong>테스트된 18개 모델 중 종합 7위</strong></li>
  <li><strong>오픈 웨이트 모델 중 1위</strong></li>
  <li><strong>실행 시간: 431분</strong> — Gemini 4 Neon(109분)보다 상당히 느림</li>
  <li><strong>추론 단계: 1,128</strong> vs. Gemini 4 Neon의 244 — 깊이 생각하지만 때로는 너무 깊이</li>
  <li><strong>도구 호출 실패율: 1.56%</strong>, 하지만 실패한 호출의 66%가 재시도로 복구 — 테스트의 어떤 Claude나 Codex 모델보다 높은 복구율</li>
</ul>

<p>참고로, <a href="/ko/blog/claude-fable-5-2-review">Claude Fable 5.2</a>는 KingBench 4에서 42/60점으로 종합 1위를 차지했습니다. Gemini 4 Neon은 37.9/60으로 2위. GLM-5.4는 강력한 오픈 웨이트 모델에 기대되는 위치에 착지했습니다.</p>

<h3>Z.ai의 내부 검증</h3>

<p>Z.ai는 30B 파라미터 규모에서 대조 실험을 실행했습니다 — 같은 아키텍처에서 루프 있음 vs. 없음 — 루프 버전은 약 10% 더 많은 학습 컴퓨팅을 사용했습니다. 결과: 벤치마크 전반에서 출력 길이가 10–14% 감소(MMLU-Pro에서 최대 14.9%), 수학, 과학적 추론, 긴 컨텍스트 작업에서 가장 큰 개선을 보였습니다.</p>

<p>이 설계는 네 가지 규모에서 검증되었습니다: 1B, 4B, 30B, 750B 파라미터.</p>

<h3>흥미로운 정성적 발견</h3>

<p>적어도 한 명의 독립 리뷰어가 GLM-5.4가 Claude Fable 5.2와 다른 테스트된 모델이 놓친 애플리케이션 버그와 보안 취약점을 발견했다고 보고했습니다. 이는 아키텍처 설계와 일치합니다 — 루프 레이어를 통한 이중 패스가 모델에게 미묘한 문제를 "인지"할 더 많은 시간을 줍니다. DataCamp의 평가에 따르면 GLM-5.4는 주요 코딩 에이전트보다 세컨드 리뷰어로 사용하는 것이 더 적합합니다.</p>

<h2>UX 점수: 7/10</h2>

<p>GLM-5.4는 Z.ai의 GLM Coding Plan 구독, ZCode(zcode.z.ai), Z.ai Chat(chat.z.ai)을 통해 접근할 수 있습니다. 인터페이스는 기능적이지만 ChatGPT나 Claude의 세련된 경험 수준에는 미치지 못합니다. 1M 토큰 컨텍스트 윈도우를 지원하며, Z.ai는 최상의 코딩 결과를 위해 클라이언트를 512,000 토큰으로 설정할 것을 권장합니다. 비주얼 코딩 작업을 위한 비전 입력도 지원합니다.</p>

<p>Z.ai 자체가 인정하는 알려진 문제: 모델이 긴 "마라톤 사고" 루프에 빠질 수 있습니다. 이것은 Loop Transformer의 트레이드오프입니다 — 더 깊은 추론을 가능하게 하는 같은 메커니즘이 때때로 과도한 숙고로 이어질 수 있습니다.</p>

<p>속도는 허용 가능합니다: Z.ai는 비피크 시간에 최대 200 tokens/s, 부하 시 70–80 tokens/s를 주장합니다.</p>

<h2>품질 점수: 8/10</h2>

<p>사용 가능한 서드파티 테스트와 초기 사용자 보고를 기반으로, GLM-5.4의 추론 품질은 진정으로 강합니다 — 특히 코드 리뷰와 보안 분석에서. Loop Transformer 아키텍처는 깊은 분석 작업에서 모델에 정성적 우위를 부여하는 것으로 보입니다. KingBench 결과와 아키텍처의 명확한 혁신을 기반으로 8점을 부여하지만, Z.ai가 공식 벤치마크를 공개하면 이 점수는 변경될 수 있습니다.</p>

<h2>가성비 점수: 7/10</h2>

<p>공개된 API 가격이 없어 가성비를 평가하기 어렵습니다. 현재 접근에는 GLM Coding Plan 구독이 필요하며, 주간 할당량은 GLM-5.3보다 50% 더 많은 것으로 보고됩니다. OpenRouter, Cursor, GitHub Copilot 또는 주요 클라우드 플랫폼(Vertex AI, Azure AI Foundry, AWS Bedrock)에서는 아직 사용할 수 없습니다. 이는 실용적 가치를 크게 제한합니다.</p>

<h2>연동 점수: 6/10</h2>

<p>이것은 GLM-5.4의 가장 약한 영역입니다. API 접근은 아직 불가능합니다 — Z.ai는 안전성 평가 후 개방할 것이라고 말합니다. 모델은 Claude Code(프로바이더 ID: "zai-coding-plan/glm-5.4")와 Z.ai 자체 도구에서 작동하지만, 대부분의 개발자가 매일 사용하는 주요 AI 플랫폼에는 없습니다. 오픈 웨이트는 계획되어 있지만 미출시 — Z.ai는 발표 날짜 없이 "안전성 강화"를 언급합니다.</p>

<h2>지원 점수: 6/10</h2>

<p>Z.ai는 모델 카드, 공식 벤치마크, 상세 문서를 공개하지 않았습니다. 이렇게 아키텍처적으로 야심 찬 모델에 대한 투명성 부족은 우려됩니다. 지원은 Z.ai 자체 에코시스템에 한정되어 있는 것으로 보입니다.</p>

<h2>Loop Transformer: GLM-5.4를 넘어 중요한 이유</h2>

<p>GLM-5.4 자체가 주요 코딩 모델을 대체할 준비가 되지 않았더라도, Loop Transformer 아키텍처는 AI 산업 전체에 중요합니다. 그 이유:</p>

<ul>
  <li><strong>효율성:</strong> 레이어를 루핑하여 750B 파라미터로 2T 파라미터 모델의 지능에 필적할 수 있다면, 비용과 에너지 절감은 엄청납니다.</li>
  <li><strong>확장성:</strong> Z.ai만이 아닙니다 — Thinking Machines의 Inkling 2 Mini(11월 20일 출시)는 26.4B 총 / 3.4B 활성 파라미터와 토큰당 3회 중간 레이어 실행으로 유사한 접근을 사용합니다. 이 패턴은 확산되고 있습니다.</li>
  <li><strong>실용적 영향:</strong> 더 작은 실효 모델은 더 저렴한 추론, 더 빠른 배포, 더 약한 하드웨어에서 실행되는 AI를 의미합니다.</li>
</ul>

<p>2026년 11월은 업계가 "더 큰 것이 항상 더 좋은가"를 의문시하기 시작한 달로 기억될 수 있습니다. Loop Transformer는 그 답이 아니오임을 시사합니다.</p>

<h2>오늘 GLM-5.4를 사용해야 할 사람은?</h2>

<ul>
  <li><strong>AI 연구자와 아키텍처 애호가:</strong> 지금 연구하기에 가장 흥미로운 모델입니다.</li>
  <li><strong>세컨드 오피니언을 원하는 코드 리뷰어:</strong> GLM-5.4는 다른 모델이 놓치는 문제를 감지합니다. 주요 코더가 아닌 리뷰어로 사용하세요.</li>
  <li><strong>관망하는 개발자:</strong> 오늘 일상적인 코딩 모델이 필요하다면 Claude Fable 5.2, Gemini 4 Neon, GPT-6.2 Sol이 더 안전한 선택입니다. 자세한 내용은 <a href="/ko/blog/gemini-4-neon-vs-gpt-6-2-astra-vs-claude-fable-5-2">Gemini 4 Neon vs GPT-6.2 Astra vs Claude Fable 5.2 비교</a>를 참조하세요. Z.ai가 API 가격과 벤치마크를 공개하면 다시 확인하세요.</li>
</ul>

<h2>종합 평가</h2>

<p>GLM-5.4는 B+를 획득했습니다 — 오늘 사용 가능한 최고의 코딩 모델이기 때문이 아니라, 차세대 AI 모델을 재형성할 수 있는 아키텍처를 도입했기 때문입니다. Loop Transformer는 실재하고, 작동하며, 이미 다른 팀에 영감을 주고 있습니다. Z.ai에 필요한 것은 문을 더 활짝 여는 것: 벤치마크 공개, API 출시, 웨이트 릴리스입니다. 그때까지는 AI가 향하는 곳을 보여주는 훌륭한 프리뷰이며, 더 높은 등급을 주기에는 사용할 수 있는 사람이 너무 적습니다.</p>
